# Настройки сервера, которых нет в репозитории

Часть поведения сайта задаётся на VPS, а не в коде. Из-за этого такие
вещи разъезжаются незаметно: код меняется, сервер остаётся прежним.
Здесь — что именно там настроено и как это проверять.

---

## Политика безопасности (CSP)

## Где она живёт

**Не в этом репозитории.** Заголовок задаётся nginx на VPS:

```
/etc/nginx/sites-available/aivfx   →   add_header Content-Security-Policy ...
```

Из-за этого её легко забыть: код меняется, политика остаётся прежней,
и браузер молча блокирует запросы. Проверить текущее значение:

```bash
curl -sSI https://aivfx.ru/ | grep -i content-security-policy
```

## Что уже сломалось на этом

27.08.2026. Форма заявок и ассистент не работали на живом сайте, хотя
на localhost всё было в порядке — там заголовка нет.

Причина: в `connect-src` был разрешён только `https://api.telegram.org`.
Это осталось со времён, когда браузер писал в Telegram напрямую. После
переноса на серверную функцию политику никто не обновил, и обращения
к `aivfx-lead-api.vercel.app` браузер отклонял. Заявки с сайта просто
не доходили.

Исправлено: `connect-src 'self' https://aivfx-lead-api.vercel.app;`
Телеграм убран — браузер к нему больше не обращается, и разрешать
его незачем.

## Правило на будущее

**Появился новый внешний адрес, к которому обращается браузер — впиши
его в CSP на сервере.** Иначе он будет отклонён, причём без ошибок
в интерфейсе: код увидит обычную сетевую неудачу и уйдёт в запасной
путь, а причина будет видна только в консоли браузера.

Это касается: серверных функций, внешних API, шрифтов, аналитики,
видеохостингов.

Как править:

```bash
ssh root@62.192.174.91
cp /etc/nginx/sites-available/aivfx /etc/nginx/sites-available/aivfx.bak-$(date +%F)
# отредактировать строку add_header Content-Security-Policy
nginx -t && systemctl reload nginx
```

Резервные копии прежних версий лежат рядом с файлом под именами
`aivfx.bak-*`.

## Что сейчас разрешено

| Директива | Кому |
|---|---|
| `connect-src` | сам сайт, `aivfx-lead-api.vercel.app` (заявки и ассистент) |
| `media-src` | сам сайт, `blob:` (полноэкранные ролики грузятся так), Kinescope |
| `img-src` | сам сайт, `data:`, Kinescope |
| `style-src` / `font-src` | сам сайт, Google Fonts |
| `frame-src` | сам сайт, Kinescope |

## Типы файлов (mime.types)

В `/etc/nginx/mime.types` не было `woff2`, и шрифты отдавались как
`application/octet-stream`. Браузер такое переживает, но при предзагрузке
(`rel=preload as=font`) несовпадение типа может привести к повторной
закачке того же файла.

Исправлено 28.08.2026: в конфиг сайта добавлен блок

```nginx
types { font/woff2 woff2; }
```

Проверить:

```bash
curl -sSI https://aivfx.ru/fonts/onest-500-cyrillic.woff2 | grep -i content-type
```

Должно быть `font/woff2`.

## Кеш страниц

HTML отдавался **без единого указания по кешу**. В таком случае браузер
решает сам и обычно держит страницу часами. А имена файлов сборки меняются
с каждым деплоем — значит посетитель со старой страницей грузит старую
версию сайта и не видит правок.

Именно на это я и напоролся 28.08.2026 при проверке: браузер показывал
сборку двухчасовой давности, хотя на сервере лежала новая.

Исправлено:

```nginx
location = /index.html { add_header Cache-Control "no-cache, must-revalidate" always; }
location ~* \.html$   { add_header Cache-Control "no-cache, must-revalidate" always; }
```

Статика при этом сохраняет годовой кеш: в её именах есть хеш, старый файл
никогда не подменяется новым содержимым.

Проверить:

```bash
curl -sSI https://aivfx.ru/ | grep -i cache-control          # no-cache
curl -sSI https://aivfx.ru/static/js/main.*.js | grep -i cache-control  # год
```

## Что на сервере уже в порядке

Проверено 28.08.2026, трогать не нужно:

- HTTP/2 включён
- gzip работает: главная едет 20 КБ вместо 70
- статика кешируется на год с `immutable`
- TLS 1.3

Медленная загрузка из Азии объясняется не настройками, а расстоянием:
сервер в Риге, задержка около 336 мс в один оборот. Для клиентов из
России это 20–40 мс.
